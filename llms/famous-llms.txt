## The API

Amaze's one public, machine-readable API is the **Spring Seller API** — a Swagger 2.0 contract with
24 operations, served live at `https://api.teespring.com/`. It is documented behind a Swagger UI at
https://api.teespring.com/docs. It is served on Spring's ORIGINAL teespring.com domain, not on any
of the newer brand domains, and its own docs prose still says "Teespring".

- [API reference (Swagger UI)](https://api.teespring.com/docs): the only developer documentation
  that exists. Four authentication steps plus the generated operation list.
- [Machine-readable contract](https://api.teespring.com/swagger_doc/): Swagger 2.0, 24 operations,
  three tags (`seller`, `v1`, `internal`).

### Authentication

1. Obtain an `app_id` from Spring. There is no self-serve key page — a human must request it.
2. `POST /v1/auth-tokens` with form fields `app_id`, `email`, `password` (the seller's Spring
   login credentials).
3. Read `access_token` from the 201 response. It expires after 24 hours. Requesting another one
   returns the current token rather than minting a new one.
4. Send `access_token` as a **query parameter** on every seller request. Public storefront reads
   take `app_id` as a query parameter instead.

There is no OAuth 2.0, no OpenID Connect, no scopes, and no `/.well-known/` discovery on any host.

### Operation groups

- `seller/v1/*` — the authenticated seller: dashboard, summary (period: today, yesterday, week,
  month, seven_days, thirty_days), campaigns, campaign roots, orders, payouts, promotions, volume
  discounts, and buyer messaging.
- `v1/*` — public storefront reads: campaigns by slug, categories, recommender collections, rush
  prices, trending search suggestions, plus the authenticated user profile and saved
  addresses/cards.
- `internal/v1/*` — inbound Stripe dispute webhook receivers. Not developer operations.

### What an agent needs to know before calling

- Errors are ad-hoc JSON, not RFC 9457, and the envelope is inconsistent: `{"error": "..."}` on
  some paths and `{"error": {"message": "..."}}` on others.
- An invalid enum value returns **404**, not 400 or 422.
- Unknown paths return **301**, not 404. Do not follow redirects; assert
  `content-type: application/json` before parsing.
- No rate-limit headers are returned and no limits are published.
- No idempotency key is supported. `POST /seller/v1/messages/send` emails real buyers, so a retry
  after a timeout can double-send. Treat it as human-in-the-loop.
- `x-request-id` and `x-correlation-id` are returned on every response and are useful for support,
  though nothing documents them.
- Credentials travel in the URL query string, so they land in logs and Referer headers.

## Client libraries

None. Amaze publishes no client SDK for the Spring Seller API in any language. The only npm package
named `teespring` is a third-party, unmaintained 2016 wrapper for a private API — not an Amaze
artifact.
